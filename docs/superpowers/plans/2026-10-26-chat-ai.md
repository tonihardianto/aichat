# Chat AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build ready-to-run Indonesian AI chat app with persisted conversations and streaming replies.

**Architecture:** Vite React app composes focused chat components around two hooks: persistent conversation CRUD and streaming chat state. `lib/agent.ts` owns all agent transport, falling back to demo streaming when no agent URL exists. shadcn/ui supplies accessible primitives, while `index.css` contains chat layout and system-driven theme variables.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind CSS, shadcn/ui, lucide-react, react-markdown, remark-gfm.

**Spec:** `docs/superpowers/specs/2026-10-26-chat-ai-design.md`

## Global Constraints

- All UI copy must be Indonesian.
- Read `VITE_AGENT_URL`; agent URL empty means demo streaming.
- Store conversation data only in browser `localStorage`; no backend, DB, or auth.
- Input max length is 8,000 characters.
- Agent adapter signature: `streamReply(messages, signal, onToken)`.
- Support agent plain-text streams and SSE `data: {"token":"..."}` ending in `[DONE]`.
- Use shadcn/ui primitives. No heavy UI library.
- Support 360px viewport, visible keyboard focus, ARIA labels, system dark mode, and `prefers-reduced-motion`.

- [ ] **Step 1: Implement demo reply when URL absent**

```ts
const url = import.meta.env.VITE_AGENT_URL?.trim();
if (!url) {
  const reply = `Ini balasan demo untuk: "${lastMessage}".`;
  for (const word of reply.split(" ")) {
    if (signal.aborted) throw new DOMException("Dibatalkan", "AbortError");
    await new Promise((resolve) => setTimeout(resolve, 35));
    onToken(`${word} `);
  }
  return;
}
```

- [ ] **Step 2: Implement POST and stream parser**

```ts
const response = await fetch(url, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ messages: messages.map(({ role, content }) => ({ role, content })) }),
  signal,
});
```

Reject non-OK or absent body with Indonesian error. For `text/event-stream`, buffer split lines, consume `data:`, stop at `[DONE]`, JSON parse token from `token`, `delta`, `content`, or `text`; non-JSON `data` is token. For other content types forward decoded chunks as tokens.

### Task 4: Add chat stream hook

**Files:**
- Create: `src/hooks/useChat.ts`

**Interfaces:**
- Consumes: `Conversation`, `Message`; `updateConversation(id, updater)` from `useConversations`; `streamReply`.
- Produces: `send(content: string)`, `stop()`, `retry()`, `regenerate()`, `isStreaming`, `error`, `clearError`.

- [ ] **Step 1: Implement sending flow**

```ts
const user: Message = { id: crypto.randomUUID(), role: "user", content, createdAt: new Date().toISOString() };
const assistant: Message = { id: crypto.randomUUID(), role: "assistant", content: "", createdAt: new Date().toISOString() };
```

Ignore blank text, active stream, and content over 8,000 characters. Append both messages before call. Set title only when first user message. Stream tokens into assistant matching its ID.

- [ ] **Step 2: Implement stop, clean-up, retry, and regeneration**

```ts
function stop() { controllerRef.current?.abort(); }
```

On abort remove empty assistant message. On non-abort error retain partial response, set `"Gagal menghubungi agent. Periksa koneksi lalu coba lagi."`, and retain latest user message for retry. `regenerate()` removes final assistant message then sends prior user content; `retry()` does same for retained failure.
